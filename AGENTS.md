# Agent guidelines

## Tests

- When provided with an implementation request with Gherkin notation (Given/When/Then), treat it as specification by example.
- In the generated tests, add the steps of the Gherkin notation as comments right before the implementation of the respective step in the test. So there is a comment with a step specification, then some go code, then potentially another comment with a step specification and so on.
- Do not create tests for the "cmd" package.

## Comments

- Each Go source file should have an AGPL license header, using Copyright (C) 2026 John Doe
- Exception: ANTLR-generated files under `core/antlr/` (files whose header
  starts with `// Code generated from ... by ANTLR ...`). These are
  auto-generated and re-created on every `go generate`; do not hand-edit
  them to add a license header.

## ANTLR parser (`core/antlr`)

- The Go files in `core/antlr` (except `generate.go` and `SpecGrammar.g4`) are
  generated by ANTLR from `SpecGrammar.g4` and are committed to the repo.
- Do **not** hand-edit the generated files. To change the parser, edit
  `SpecGrammar.g4` and regenerate with `go generate ./core/antlr/...`
  (see README for the ANTLR jar setup).
