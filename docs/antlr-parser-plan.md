# Plan: Minimal ANTLR parser for spec → Gherkin (GH-38)

Replace the hand-rolled TypeScript spec scanner in `core/parser.go` with a
parser generated by ANTLR, for reverse-engineering Gherkin feature files from
`*.spec.ts` test files.

## Decisions

- **Grammar:** a minimal, purpose-built **island/tolerant grammar** — not the
  full `grammars-v4/javascript/typescript` grammar. Reason: that grammar has no
  Go target and requires hand-porting `TypeScriptLexerBase` +
  `TypeScriptParserBase` (undocumented ASI / regex-vs-divide / template-string
  logic). We only need to recognise `describe` / `it` / `beforeEach` calls,
  their string-literal names, callback-block nesting, and `//` step comments —
  so a small grammar covers it with far less work and risk.
- **Generated sources:** committed to the repo. End users need only Go. Java +
  the ANTLR jar are a dev-only dependency used to regenerate.

## Current state

- `core/parser.go` — line scanner. Counts `{`/`}` depth, string-matches
  `describe(` / `it(` / `beforeEach(`, regex-extracts `// Given/When/Then`
  comments. Produces `[]*messages.GherkinDocument`.
- Consumer: `cmd/rev.go` → `core.ParseSpecFile(path, relaxed)`.
- Behaviour pinned by `core/parser_test.go`: nesting → separate features,
  kebab-case URIs, relaxed mode on/off, name sanitization, `fit`/`xit`
  exclusion.
- No ANTLR dependency yet. Go 1.26, module
  `github.com/experimental-software/gherkin`.

## Keep unchanged

- `ParseSpecFile(path, relaxed) ([]*messages.GherkinDocument, error)` signature
  — `cmd/rev.go` and all tests stay as-is. Swap only internals.
- `emitDescribe`, `buildFeatureDoc`, `normalizeUri`, kebab/URI logic,
  `matchStepComment`, `normalizeScenarioTitle` — reuse as-is. Only the front
  half (line scan → `frame` tree) is replaced.

## Two facts that shape the design

1. **The upstream grammar has no Go base classes** (only CSharp / Cpp / Java /
   TypeScript). Both grammars declare a `superClass`. Avoided entirely by using
   a minimal grammar with no `superClass`.
2. **Gherkin steps live in `//` comments → hidden channel.** Comments never
   reach the parse tree. Steps must be pulled from the `CommonTokenStream` by
   token index and correlated to each `it` / `beforeEach` callback's token span.

## Target layout

```
core/
  antlr/
    SpecGrammar.g4          # minimal island grammar (hand-written)
    spec_lexer.go           # ANTLR-generated, committed
    spec_parser.go          # ANTLR-generated, committed
    spec_base_listener.go   # generated, committed
    generate.go             # //go:generate antlr4 -Dlanguage=Go ...
  spec_visitor.go           # tree walk -> []*frame
  parser.go                 # ParseSpecFile: swap internals
```

- Add runtime dependency `github.com/antlr4-go/antlr/v4`.
- Java + ANTLR jar are dev-only (generated `.go` is committed).

## Grammar sketch (`SpecGrammar.g4`)

- **Lexer tokens:** `DESCRIBE` `IT` `BEFOREEACH` (exact keywords — removes the
  fragile `fit`/`xit` `isIdentChar` hack), `STRING` (single and double quote),
  `LPAREN RPAREN LBRACE RBRACE COMMA ARROW`, `LINE_COMMENT` / `BLOCK_COMMENT`
  → hidden channel, `IDENT`, and a catch-all `OTHER` → skip/hidden.
- **Parser rules:** `program: block* EOF;` where a `suite` is
  `(DESCRIBE|IT|BEFOREEACH) LPAREN STRING? ... LBRACE body RBRACE ... RPAREN`;
  `body` is a nested `suite` or filler. Brace balancing is done by rule
  recursion, not manual counting.

## Steps

1. **Tooling.** Install the ANTLR jar (dev). Add `generate.go` with a
   `//go:generate` directive. Document regeneration in README / AGENTS.md.
2. **Write `SpecGrammar.g4`** — the island grammar above. Iterate against
   `core/testdata/*.spec.ts` until all parse.
3. **Generate + commit** — `antlr4 -Dlanguage=Go -visitor` (or listener);
   commit output under `core/antlr/`.
4. **Write `spec_visitor.go`** — walk the tree with a describe-frame stack
   (replaces the brace-depth loop):
   - Each `suite` node → frame kind by keyword, name from the `STRING` first arg.
   - Nesting from tree structure → ancestors.
   - For `it` / `beforeEach`: pull hidden-channel comment tokens within the
     callback-block token span from the `CommonTokenStream`, run the existing
     `matchStepComment` regex → steps.
   - Build the same `*frame` tree, hand off to the existing `emitDescribe`.
5. **Trim `parser.go`** — drop the brace loop, `extractQuotedName`,
   `isIdentChar`. Keep `matchStepComment`, `normalizeScenarioTitle`.
6. **Error listener** — preserve the partial-result contract (`rev.go` uses
   whatever docs the parser produced even on error). Collect syntax errors,
   still return the built frames.

## Testing

- **Acceptance bar:** all existing `core/parser_test.go` cases pass unchanged
  — nesting → separate features, kebab URIs, relaxed on/off, sanitization,
  `fit`/`xit` exclusion.
- **Add cases:** multi-line `describe(` calls, template-literal test names,
  `//`-comment edge cases.

## Risks (low with the minimal-grammar approach)

- Island-grammar filler rules can be finicky — mitigated by iterating against
  `testdata`.
- Comment ↔ block token-index correlation is fiddly but standard.
- Larger dependency footprint + a codegen step vs. the current zero-dependency
  line scanner.
